🚀 DEVELOPER INTEGRATION BLUEPRINT

How to Connect Any Website or Portal to Central SSO

Want to add a new website (e.g. Agrotutor, e-Agrology, or any custom client portal) to this SSO? Follow this 5-step integration process. Central SSO handles single identity & global roles; your platform retains its custom subroles & project permissions.

1
Register Platform in SSO
Go to Platforms & Domains in this console. Click + Add Platform, set your platform slug (e.g. agrotutor) and allowed domains (e.g. https://revamp.agrotutor.co,http://localhost:3000). Save and copy your unique Platform API Key.
2
Set Client System Environment
Add the SSO connection variables to your client application's .env file:
CLIENT .ENV 
SSO_BASE_URL="http://localhost:8005"
SSO_APP_ID="agrotutor"
SSO_API_KEY="agrotutor-api-secret-key-2026"
3
Delegate Login to SSO API
In your client application's login handler, forward user credentials to POST /api/sso/auth/login. SSO checks passwords in PostgreSQL and issues a signed JWT containing user_id and global_role.
PYTHON / FASTAPI EX. 
res = httpx.post(f"{SSO_URL}/api/sso/auth/login", json={
    "identifier": email_or_username,
    "password": password,
    "app_id": SSO_APP_ID
})
# Returns token, user_id, and global_role
4
Roles vs Local Subroles
Crucial Architecture Rule:
• Global Role: (admin or standard) is managed here in Central SSO.
• Subroles & Permissions: (e.g. Project Manager, Surveyor on e-Agrology; Logic Manager on Agrotutor) are stored in your own platform's database mapped to the user's user_id.
5
Directory Sync via API Key
To list users in your client portal or dropdowns, fetch directly from SSO using your X-SSO-Api-Key:
cURL / HTTP 
GET /api/sso/users
Header: X-SSO-Api-Key: {SSO_API_KEY}
POST /api/sso/auth/login 🌐 Client Public Endpoint

Primary SSO authentication endpoint used by connected client platforms (e-Agrology, Agrotutor, etc.) to verify credentials and issue a signed session JWT containing user identity and global role.

Request Payload (JSON) 
{
  "identifier": "simnan@eagrology.in",
  "password": "UserPassword123!",
  "app_id": "eagrology"
}
Live Response Result 200 OK 
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "user_id": "USR10482",
    "email": "simnan@eagrology.in",
    "username": "simnan_k",
    "phone": "+919876543210",
    "full_name": "Simnan Khan",
    "global_role": "standard",
    "role": "standard",
    "role_label": "Standard User",
    "app_id": "eagrology",
    "is_active": true
  }
}
curl -X POST http://localhost:8005/api/sso/auth/login -H "Content-Type: application/json" -d '{"identifier":"user@example.com","password":"pw","app_id":"agrotutor"}'
POST /api/sso/auth/verify 🌐 Token Verification

Validates an existing SSO JWT token, ensuring it has not expired and the account remains active. Returns complete user profile, assigned global role, subroles, and permissions.

}
Response Result 200 OK

  "valid": true,
  "user": {
    "user_id": "USR10482",
    "email": "simnan@eagrology.in",
    "username": "simnan_k",
    "full_name": "Simnan Khan",
    "global_role": "standard",
    "role": "standard",
    "role_label": "Standard User",
    "app_id": "eagrology",
    "subroles": [],
    "permissions": [],

curl -X POST http://localhost:8005/api/sso/auth/verify -H "Content-Type: application/json" -d '{"token":"<jwt_token>"}'
